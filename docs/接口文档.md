# WIFICSI 接口文档

本文定义看板服务器对外暴露的 HTTP REST API 与 WebSocket JSON v1 契约。所有响应为 UTF-8 JSON；MAC 为小写冒号格式（如 `28:84:85:87:2b:f4`）；时间戳为 Unix epoch 毫秒；路径统一带 `/api/v1`。

存在状态语义固定映射：

| 节点生命周期 `lifecycle` | API `presence` | 中文 `presence_label` | 含义 |
| --- | --- | --- | --- |
| `ACTIVE` | `PRESENT` | 有人 | 官方活动检测 ACTIVE |
| `INACTIVE` | `ABSENT` | 无人 | 官方活动检测 INACTIVE |
| `INITIALIZING` | `UNKNOWN` | 初始化中 | 在线但尚无稳定状态 |
| `OFFLINE` | `OFFLINE` | 离线 | 超过 5 秒无合法数据报 |

> 禁止把 `UNKNOWN`/`OFFLINE` 当作“无人”。ACTIVE/INACTIVE 是活动代理结果，不等同于经过准确率验证的静态人体检测。

---

## 1. REST API

### 1.1 `GET /api/v1/health`

确认进程、UDP 绑定与 publisher 正常（不代表节点在线）。

```json
{
  "status": "ok",
  "server_time_ms": 1786890000123,
  "udp_bound": true,
  "udp_endpoint": "10.204.75.168:5500",
  "publisher_hz": 10.0,
  "known_nodes": 4,
  "online_nodes": 3
}
```

### 1.2 `GET /api/v1/nodes`

页面首次加载与 WebSocket 重连后的权威全量节点快照。节点按 `node_id` 升序排序，OFFLINE 节点仍保留。

```json
{
  "schema_version": 1,
  "server_time_ms": 1786890000123,
  "nodes": [
    {
      "node_id": "28:84:85:87:2b:f4",
      "boot_id": 305419896,
      "lifecycle": "ACTIVE",
      "presence": "PRESENT",
      "presence_label": "有人",
      "last_seen_age_ms": 37,
      "firmware": "1.0.0",
      "ap_bssid": "5e:e3:88:d9:5b:42",
      "channel": 4,
      "rssi_dbm": -43,
      "csi_rate_hz": 99.8,
      "accepted_packets": 123456,
      "sequence_gaps": 14,
      "duplicates": 0,
      "out_of_order": 1,
      "queue_dropped": 0,
      "udp_send_errors": 13,
      "free_heap_bytes": 7123456,
      "csi_available": true,
      "sensing_available": true
    }
  ]
}
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `node_id` | string | 6 字节 STA MAC，节点主键 |
| `boot_id` | int | 节点每次启动生成的新 ID |
| `lifecycle` | string | 原始生命周期枚举 |
| `presence` | string | `PRESENT/ABSENT/UNKNOWN/OFFLINE` |
| `presence_label` | string | 中文显示 |
| `last_seen_age_ms` | int\|null | 距最后一次合法数据的毫秒数 |
| `firmware` | string\|null | `major.minor.patch`，缺 HELLO 时为 null |
| `ap_bssid` | string\|null | 节点关联 AP 的 BSSID |
| `channel` | int\|null | 最新 CSI 帧信道 |
| `rssi_dbm` | int\|null | 最新 CSI 帧 RSSI |
| `csi_rate_hz` | float\|null | 最近完整 1 秒窗口的源 CSI 帧率（非 UI 10 Hz 帧率） |
| `accepted_packets` | int | 服务器接收的合法包数 |
| `sequence_gaps` / `duplicates` / `out_of_order` | int | 序列缺口 / 重复 / 乱序计数 |
| `queue_dropped` / `udp_send_errors` | int | 设备队列丢弃 / 设备 UDP 发送错误 |
| `free_heap_bytes` | int\|null | 设备空闲堆（缺 HEARTBEAT 时为 null） |
| `csi_available` / `sensing_available` | bool | 是否已收到 CSI / 感知状态 |

缺 HELLO/CSI/HEARTBEAT 时，对应字段返回 `null`/`false`，不填 0 冒充测量值。

### 1.3 `GET /api/v1/nodes/{node_id}`

返回与列表相同的节点对象，附加最新感知诊断（不产生第二套存在结论）：

```json
{
  "schema_version": 1,
  "server_time_ms": 1786890000123,
  "node": { "node_id": "28:84:85:87:2b:f4", "presence": "PRESENT" },
  "sensing": {
    "stable_state": "ACTIVE",
    "process_state": "ACTIVE",
    "init_stage": "STABLE",
    "jitter": 0.112,
    "wander": 0.087,
    "reason": 0
  }
}
```

- 合法但未知 MAC：HTTP 404，`{"detail":{"code":"node_not_found"}}`
- MAC 格式错误：HTTP 422，`{"detail":{"code":"invalid_node_id"}}`
- 不返回原始 `iq` 字节。

### 1.4 `GET /api/v1/nodes/{node_id}/latest-csi`

页面首次打开详情时立即取得一个派生帧；后续由 WebSocket 更新。

```json
{
  "schema_version": 1,
  "node_id": "28:84:85:87:2b:f4",
  "boot_id": 305419896,
  "server_time_ms": 1786890000123,
  "device_time_us": 927345678,
  "rssi_dbm": -43,
  "channel": 4,
  "sample_pair_count": 64,
  "amplitude": [12.04, 18.38, 9.0],
  "mean_amplitude": 14.2,
  "rms_amplitude": 16.8,
  "variance": 27.1,
  "source_frames": 10,
  "ui_frames_coalesced": 9
}
```

- `amplitude` 长度由 CSI 帧决定，前端不得假设固定 64/128/192。
- 尚无派生 CSI：HTTP 404，`{"detail":{"code":"csi_not_available"}}`。

## 2. WebSocket JSON v1

地址：`ws://<host>:8000/api/v1/ws`

### 2.1 连接与订阅

连接成功后服务器先发送 `hello` 与 `nodes_snapshot`，随后客户端可发送：

```json
{
  "type": "subscribe",
  "schema_version": 1,
  "node_ids": ["28:84:85:87:2b:f4", "30:ae:a4:00:11:22"]
}
```

- `node_ids=[]`：订阅当前及后续发现的全部节点。
- 非空数组：仅订阅指定节点，最多 16 个，自动去重。
- 再次发送 `subscribe` 原子替换旧订阅。
- 未知节点 ID 可保留，节点出现后自动推送。
- 非法 JSON / 未知消息类型 / 错误版本 / 非法 MAC 返回 `error`；连续 3 次协议错误后关闭连接，关闭码 1008。
- 服务器每 20 秒发送 `ping`，客户端可据此做保活。

前端总览页订阅全部节点；详情页复用同一连接，不为每张卡片建新连接。

### 2.2 统一事件信封

```json
{
  "type": "node_status",
  "schema_version": 1,
  "event_id": 8123,
  "server_time_ms": 1786890000123,
  "data": {}
}
```

`event_id` 为进程内递增 uint64，仅用于发现一次连接中的跳号；重启后可从 1 重新开始，不提供历史补发。

### 2.3 `hello`

```json
{
  "type": "hello",
  "schema_version": 1,
  "event_id": 1,
  "server_time_ms": 1786890000123,
  "data": {
    "server_instance_id": "7f0f7ad7-8326-4d41-bc46-e28948834bc5",
    "publish_hz": 10,
    "offline_after_ms": 5000
  }
}
```

`server_instance_id` 变化表示后端重启，前端应清空短时图表并通过 REST 重拉全量。

### 2.4 `nodes_snapshot`

`data` 与 `GET /api/v1/nodes` 的节点列表一致：

```json
{
  "type": "nodes_snapshot",
  "schema_version": 1,
  "event_id": 2,
  "server_time_ms": 1786890000123,
  "data": { "nodes": [ { "node_id": "28:84:85:87:2b:f4", "presence": "PRESENT" } ] }
}
```

在连接建立、订阅成功和服务器认为需要重同步时发送，不以 10 Hz 重复。

### 2.5 `node_status`

每个在线节点最多 1 Hz 推送，生命周期或 `boot_id` 变化时立即推送。`data` 为 NodeSummary（字段同 1.2）。OFFLINE 事件在 5 秒过期规则触发后推送。

### 2.6 `csi_batch`

每个有新数据的订阅节点最高约 10 Hz：

```json
{
  "type": "csi_batch",
  "schema_version": 1,
  "event_id": 8124,
  "server_time_ms": 1786890000223,
  "data": {
    "node_id": "28:84:85:87:2b:f4",
    "boot_id": 305419896,
    "device_time_us": 927345678,
    "rssi_dbm": -43,
    "channel": 4,
    "amplitude": [12.04, 18.38, 9.0],
    "mean_amplitude": 14.2,
    "rms_amplitude": 16.8,
    "variance": 27.1,
    "source_frames": 10,
    "ui_frames_coalesced": 9
  }
}
```

- 不发送 base64 原始 IQ，也不一次批量发送 100 个完整幅值数组。
- `source_frames`：本 UI 周期观察到多少个源 CSI 帧。
- `ui_frames_coalesced`：其中多少帧被“最新值合并”替换，用于确认是主动 UI 限频而非设备/UDP 丢包。

### 2.7 `error`

```json
{
  "type": "error",
  "schema_version": 1,
  "event_id": 8125,
  "server_time_ms": 1786890000300,
  "data": { "code": "invalid_subscription", "message": "node_ids must contain at most 16 valid MAC addresses" }
}
```

错误信息不包含 Python traceback、局域网凭据或原始 UDP 数据。

## 3. 背压与限频说明

- UDP 接收路径不做 JSON 编码、磁盘 I/O 或 await；慢浏览器不会反压 UDP ingest。
- 每个节点只保留“最新原始 CSI 槽”，publisher 每 100 ms 派生一次，输出约 10 Hz。
- 每个 WebSocket 连接使用“按 `(event_type, node_id)` 合并”的邮箱，旧 `csi_batch` 未发送时被新批次覆盖。
- 每节点派生环形缓冲最多 100 点；前端每节点趋势最多 600 点。
