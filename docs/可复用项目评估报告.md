## 二、分项目详细评估

### 1. espressif/esp-csi（官方，1498★）—— 首选基础

- **是什么**：Espressif 官方 CSI 应用仓库，展示 ESP-WIFI-CSI 的采集、处理算法与应用案例
- **实现情况**：✅ 真实。含 3 类例程（get-started 采集 / esp-radar 应用 / 官方文档 6 篇）；`wifi_sensing_demo` 提供片上**人体存在+运动检测**（esp_wifi_sensing 组件，FSM 状态机 + jitter 特征 + 现场标定）
- **可复现性**：✅ 高。全系列 ESP32 支持，文档完善，Apache-2.0
- **是否造假**：无
- **复用建议**：**本项目的第一基础**——采集用 `csi_recv/csi_send`，存在检测用 `esp_wifi_sensing` 组件

### 2. ESPectre（francescopace）—— 落地首选

- **是什么**：基于 Wi-Fi 频谱分析（CSI）的运动检测系统，**ESPHome 组件 + Home Assistant 原生集成**
- **实现情况**：✅ 真实且成熟。有 CI、codecov、release、SETUP/TUNING/ALGORITHMS 完整文档；新 ML 检测器（神经网络，片上运行，无需标定，实验性）
- **可复现性**：✅ 极高。~€10 ESP32（S3/C6 推荐），10-15 分钟，YAML 配置，无需编程；GPLv3
- **是否造假**：无
- **复用建议**：**智能家居落地的首选**；ALGORITHMS.md 的 CSI 信号处理文档 + 传感器放置指南（3-8m、1-1.5m 高度、外置天线）极有参考价值

### 3. ESP32-CSI-Tool（StevenMHernandez，539★）—— 采集参考

- **是什么**：学术级 ESP32 CSI 采集工具（WOWMOM 论文背书），3 种模式（active_sta 发送 / active_ap 接收 / passive 被动监听）
- **实现情况**：✅ 真实。CSV 输出（串口+SD 卡）、实时可视化脚本、时间同步方案
- **可复现性**：✅ 高。但依赖 **ESP-IDF v4.3**（较老，与新版 esp-csi 例程有代差）
- **是否造假**：无
- **复用建议**：采集配置经验（波特率 921600、FreeRTOS tick 1000Hz、CSI 使能）直接采纳；代码本身建议改用 esp-csi 新版例程

### 4. wifi-csi-presence-detection（wrlxavier，5★）—— 方法最清晰

- **是什么**：UFMG 本科论文，2×ESP32-S3 组 TX/RX 链路的**存在检测二分类**
- **实现情况**：✅ 真实。完整 pipeline（采集→预处理→特征→分类），方法学严谨（Butterworth/Daubechies 去噪、162 子载波×4 特征=648 维、RF/SVM/XGBoost/MLP）
- **可复现性**：⚠️ 中。pipeline v0 已完成（含 pilot 数据 1200 窗口），但 **ML 训练尚未开始**（截至 2026-05）
- **是否造假**：无（诚实标注进度）
- **复用建议**：**特征工程方法直接照抄**；数据采集规范（HT40、~29Hz、2s 窗、平衡类）值得遵循

### 5. WaveSight（ErfanDL，16★）—— 自建系统参考

- **是什么**：ESP32-S3 CSI 雷达，人体**存在 + 运动**检测，Web UI + 自动标定 + GPIO/LED 输出
- **实现情况**：✅ 真实。jitter + RSSI 特征、60s 空房自动标定、完整 Web Dashboard、ESP-IDF v5.4.4
- **可复现性**：✅ 高。文档详细（含标定流程、按钮功能、故障排查）
- **是否造假**：无
- **复用建议**：**存在检测的自建方案蓝本**（若不用官方组件），自动标定逻辑和"someone timeout"机制可直接参考

### 6. EvilRoom（HackWidMaddy，15★）—— ML 分类框架

- **是什么**：ESP32（AP 模式）+ CSI，**4 区域人体检测**，XGBoost + PCA + SMOTE
- **实现情况**：✅ 真实。80.5% 准确率、混淆矩阵、训练/预测脚本齐全、视频 PoC、附训练数据
- **可复现性**：✅ 高。用 esp-csi 的 csi_recv_router 采集，Python 训练+实时预测
- **是否造假**：无
- **复用建议**：**区域/动作分类的 ML 框架参考**（PCA 降维 + SMOTE 平衡 + XGBoost）

### 7. Wriple（AHG-BSCS，4★）—— 深度学习系统

- **是什么**：跨平台桌面应用，WiFi CSI + mmWave（HLK-LD2420）双模态，**Conv-LSTM** 穿墙存在检测
- **实现情况**：✅ 真实。完整系统（校准 15s、噪声门限、每 2s 判定、数据采集工具、heatmap 可视化），有 release 安装包
- **可复现性**：⚠️ 中。系统完整但组件多（ESP32 固件 + Flask 后端 + TensorFlow + PyInstaller），需 email 联系作者
- **是否造假**：无
- **复用建议**：**深度学习路线（Conv-LSTM）与数据采集规范的参考**；其"噪声<50 才可靠"的工程经验有价值

### 8. DapFall（zyb-sysu，7★）—— 跌倒检测学术

- **是什么**：论文《DapFall: Dynamic Amplitude Probability Density Profile》（IEEE Sensors Journal 2025）源码
- **实现情况**：✅ 真实（论文+代码+数据）。提出 **DAPD 特征**，降低静态分量，跨环境跌倒检测
- **可复现性**：⚠️ 中。数据在 Google Drive（需翻墙），需自行跑通
- **是否造假**：无（正规学术）
- **复用建议**：**跌倒检测的核心特征思路（DAPD）直接借鉴**；这是当前开源界少有的"有论文背书的跌倒检测"方案

### 9. ruview-lite（SeaHorseCapn）—— 教学参考

- **是什么**：RuView 的"诚实教学版"，存在/呼吸/**跌倒（模拟）**/心跳的 DSP 演示
- **实现情况**：✅ 真实但**明确声明"不处理真实 WiFi 包"**（纯模拟 + 教学）；有 docs/esp32_setup.md 指导真实硬件采集
- **可复现性**：✅ 高（pip 安装即跑 demo）
- **是否造假**：无（诚实标注）
- **复用建议**：**理解 DSP 管线（存在/呼吸/跌倒的信号处理逻辑）的教学素材**；不能直接用于真实感知

### 10. FallDetection（mabagheri，8★）—— 造假/空壳案例

- **是什么**：声称"WiFi 信号跌倒检测核心代码"
- **实现情况**：❌ **空壳**。README 原文："For company security reasons, all core functions has been taken out :)"（核心函数因公司安全原因全部移除）
- **可复现性**：❌ 不可复现
- **是否造假**：**是**（有 star 无实质，核心代码缺失，仅剩分类框架外壳）
- **复用建议**：**不可复用**；作为"开源项目良莠不齐"的典型案例

### 11. RuView（ruvnet，88.9k★）—— 争议项目（已深度分析）

- **是什么**：宣称"WiFi CSI 空间感知平台"（存在/呼吸/姿态/人数/穿墙）
- **实现情况**：⚠️ **部分真实部分造假**。真实：ESP32 固件、CSI 二进制解析（esp32_parser.rs）、DSP 管线（相位清洗/带通/呼吸提取）、确定性证明体系；造假：**"17 关键点姿态"= 硬编码模板 + sin() 动画**、模型权重链断裂、运行时推理是 confidence=0 的 stub、v1 曾用随机数冒充 CSI 解析
- **可复现性**：⚠️ 低。基础存在/运动检测可复现（多位用户实证），姿态/人数不可复现
- **是否造假**：**是**（姿态估计等旗舰功能名不副实；已在舆论压力下转向诚实披露）
- **复用建议**：**仅参考其真实的 DSP 管线与固件 CSI 提取**；姿态/人数/穿墙宣传不可信；本质是"真实信号处理地基 + 夸张 AI 外壳"

## 三、"是否造假"的判定方法与结论

本项目调研中识别出两类问题项目：

1. **空壳项目**（如 FallDetection）：有 star、有 README 宣传，但核心代码缺失/被移除 → **直接剔除**
2. **夸大宣传项目**（如 RuView）：部分功能真实、部分功能造假（硬编码动画冒充 ML 推理、权重链断裂）→ **只复用真实部分，警惕宣传**

**判定经验**：
- 看是否有**论文背书**（DapFall、ESP32-CSI-Tool、wifi-csi-presence 均为学术项目，可信）
- 看是否有**真实数据/视频 PoC/混淆矩阵**（EvilRoom、WaveSight 有，可信）
- 看是否**诚实披露局限**（ruview-lite 明说"模拟"、wifi-csi-presence 明说"训练未开始"，可信）
- 警惕**核心代码缺失、从不提供细节、star 与真实使用量脱节**（FallDetection、RuView）

## 四、可复用项目的最终建议（按本项目需求）

| 需求 | 首选复用 | 理由 |
|------|---------|------|
| CSI 采集固件 | esp-csi `csi_recv/csi_send` | 官方、活跃、S3 全支持 |
| 存在检测（片上） | esp_wifi_sensing 组件 | 官方现成、无需训练 |
| 存在检测（ML，需更高精度） | wifi-csi-presence 方法 | 特征工程最严谨 |
| 运动检测（智能家居） | ESPectre | 10 分钟接入 HA |
| 自建 Dashboard | WaveSight | Web UI + 自动标定 |
| 动作/区域分类框架 | EvilRoom | PCA+SMOTE+XGBoost |
| 跌倒检测 | DapFall（DAPD 特征） | 唯一有论文的跌倒方案 |
| 深度学习路线 | Wriple（Conv-LSTM） | 时序建模参考 |
| DSP 管线理解 | ruview-lite + RuView 真实部分 | 教学 + 真实固件/DSP |

**一句话结论**：存在感知与运动检测**有成熟可信的官方/开源方案可直接复用**（esp-csi + esp_wifi_sensing + ESPectre）；**跌倒检测与大动作分类是本项目的自研攻坚点**，可从 DapFall 的 DAPD 特征和 EvilRoom/Wriple 的 ML 框架出发构建，同时警惕 FallDetection/RuView 这类空壳或夸大项目。
