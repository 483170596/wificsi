# WIFICSI 部署指导

本文说明如何把 ESP32-S3 节点固件、感知服务器和网页看板部署到局域网，使任意同网段浏览器能够查看多节点的实时 CSI 数据与存在感知状态。

## 1. 系统概览

```text
ESP32-S3 节点（1～4 个，WCSI v1 UDP）
   │  CSI/HELLO/SENSING_STATE/HEARTBEAT → UDP 10.204.75.168:5500
   ▼
感知服务器（Windows，Python 3.12/3.13 单进程）
   ├─ UDP ingest + 严格解码 + 节点生命周期
   ├─ NodeStreamHub（10 Hz 有界派生）
   └─ FastAPI：REST + WebSocket，托管 web/dist
   │  HTTP/WebSocket 10.204.75.168:8000
   ▼
同局域网浏览器：多节点总览 + 实时 CSI 幅值 + 信号趋势 + 健康指标
```

端口规划：

| 用途 | 地址 | 协议 |
| --- | --- | --- |
| 节点遥测上报 | `10.204.75.168:5500` | UDP |
| 节点命令接收 | 每节点 `:5501` | UDP（本 Web MVP 不使用） |
| 网页与 API | `10.204.75.168:8000` | HTTP / WebSocket |

## 2. 环境要求

### 服务器

- Windows 10/11
- Python 3.12 或 3.13（建议通过 `uv` 管理）
- `uv`（本项目使用 `D:\Develop\uv\uv.exe`）
- Node.js ≥ 18 与 npm（仅构建前端时需要）

### 节点

- ESP32-S3（建议 N8R8）
- ESP-IDF 5.4.4
- 2.4 GHz Wi-Fi 接入点（本项目为 `PRTS`）

## 3. 节点固件烧录

固件位于 `firmware/node/`，其 `idf_component.yml` 声明 `esp_wifi_sensing 0.1.1~2` 依赖，由 ESP-IDF 组件管理器自动下载，无需额外 `third_party` 子模块。

```powershell
# 初始化 ESP-IDF 5.4.4 环境（路径按本机实际调整）
& 'C:\Espressif\tools\Microsoft.v5.4.4.PowerShell_profile.ps1'
$env:IDF_CCACHE_ENABLE='0'

# 构建
idf.py -C firmware/node build

# 烧录（COM8 按实际串口替换）
idf.py -C firmware/node -p COM8 flash
```

要点：

1. 每块板子烧录同一份固件；STA MAC 由硬件决定，是节点唯一标识。
2. 烧录后记录每块板的 STA MAC（6 字节，形如 `28:84:85:87:2b:f4`）。
3. 正式 headless 验收时不要保持串口监视器打开；串口仅用于烧录和有界启动诊断。
4. `sdkconfig.defaults` 已指向目标 AP `PRTS` 与上报地址 `10.204.75.168:5500`，如需改 AP/地址请修改后重新构建。

> 不要将 Wi-Fi 密码、原始 CSI I/Q、串口日志或 JSONL 指标提交进 Git。

### 3.1 配置上报服务器地址（服务器 IP 变化时）

节点上报的目标地址由 Kconfig 配置项控制，定义在 `firmware/node/main/Kconfig.projbuild`：

| 配置项 | 默认值 | 含义 |
| --- | --- | --- |
| `WCSI_SERVER_ADDRESS` | `10.204.75.168` | 感知服务器 IPv4 地址 |
| `WCSI_SERVER_PORT` | `5500` | 感知服务器 UDP 端口 |
| `WCSI_WIFI_SSID` / `WCSI_WIFI_PASSWORD` | `PRTS` / `arknights` | 节点连接的 Wi-Fi |

修改方式二选一：

1. **menuconfig（交互式）**：

   ```powershell
   idf.py -C firmware/node menuconfig
   # 进入 "WCSI node configuration"，修改 WCSI_SERVER_ADDRESS 等
   idf.py -C firmware/node build
   idf.py -C firmware/node -p COM8 flash
   ```

2. **在 `sdkconfig.defaults` 中覆盖**：向 `firmware/node/sdkconfig.defaults` 追加（或新建一个 defaults 文件组合）：

   ```text
   CONFIG_WCSI_SERVER_ADDRESS="192.168.1.50"
   CONFIG_WCSI_SERVER_PORT=5500
   ```

改完后需重新构建并烧录。**固件上报地址必须与服务器 `--udp-host` 监听地址保持一致**。

## 4. 感知服务器部署

### 4.1 安装依赖

```powershell
Set-Location D:\Projects\WIFICSI
D:\Develop\uv\uv.exe sync --all-groups
```

`pyproject.toml` 提供三个命令入口：

| 命令 | 说明 |
| --- | --- |
| `wificsi-server` | Stage 2 无头 UDP 服务器（验收/采集用） |
| `wificsi-simulator` | WCSI 节点模拟器（无硬件联调用） |
| `wificsi-dashboard` | Stage 3 看板服务器（REST + WebSocket + 静态托管） |

### 4.2 构建前端（一次性）

看板服务器可直接托管 `web/dist` 静态文件。若尚未构建：

```powershell
Set-Location D:\Projects\WIFICSI\web
npm install
npm run build
```

生成 `web/dist`。服务器启动时会自动探测 `<仓库>/web/dist`；也可用 `--web-dist` 显式指定。

### 4.3 启动看板服务器

```powershell
D:\Develop\uv\uv.exe run wificsi-dashboard `
  --udp-host 10.204.75.168 --udp-port 5500 `
  --http-host 10.204.75.168 --http-port 8000
```

命令行参数：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `--udp-host` | `10.204.75.168` | UDP 遥测监听地址 |
| `--udp-port` | `5500` | UDP 遥测监听端口 |
| `--http-host` | `10.204.75.168` | HTTP/WebSocket 监听地址 |
| `--http-port` | `8000` | HTTP/WebSocket 监听端口 |
| `--publish-hz` | `10.0` | 实时推送频率 |
| `--web-dist` | 自动探测 | 前端静态目录 |

本机/模拟器联调时，把 `--udp-host` 与 `--http-host` 改为 `127.0.0.1` 即可。

### 4.4 服务器 IP 变化与局域网访问

服务器地址完全由命令行参数配置；前端页面全部使用相对 URL（`window.location.host`）自动跟随访问地址，因此**更换服务器 IP 无需改动前端代码**。

- **绑定本机内网 IP（推荐，最安全）**：

  ```powershell
  D:\Develop\uv\uv.exe run wificsi-dashboard `
    --udp-host 192.168.1.50 --udp-port 5500 `
    --http-host 192.168.1.50 --http-port 8000
  ```

- **绑定所有网卡 `0.0.0.0`（最省事）**：

  ```powershell
  D:\Develop\uv\uv.exe run wificsi-dashboard `
    --udp-host 0.0.0.0 --udp-port 5500 `
    --http-host 0.0.0.0 --http-port 8000
  ```

  `0.0.0.0` 会监听本机所有网卡，任何局域网设备都能访问；仅在可信局域网、且服务器无公网网卡（或防火墙已限制）时使用。

局域网任意设备访问页面，只需三步：

1. 服务器按上面任一方式绑定（内网 IP 或 `0.0.0.0`）。
2. 防火墙放行 TCP `8000`（网页）与 UDP `5500`（节点遥测）。
3. 任意设备浏览器打开 `http://<服务器内网IP>:8000`。

> 页面里的 REST 与 WebSocket 请求都使用相对地址，自动指向你正在访问的主机；换 IP 后直接访问新地址即可。注意：节点固件的上报地址 `CONFIG_WCSI_SERVER_ADDRESS` 也必须改为同一新 IP（见第 3 节）。

## 5. 启动与日常使用

1. 让 1～4 个 ESP32-S3 上电并连接 `PRTS`。
2. 在服务器上启动 `wificsi-dashboard`。
3. 同局域网浏览器打开 `http://10.204.75.168:8000`。
4. 页面自动列出已发现节点；点击节点查看实时 CSI 幅值与最近 60 秒信号趋势。

节点在约 35 秒内（HELLO 周期）出现在页面；断线约 5 秒后显示“离线”，恢复后先“初始化中”再进入“有人/无人”。

## 6. 网络与防火墙

- 服务器 HTTP 建议绑定内网网卡 IP（如 `10.204.75.168`）。若用 `--http-host 0.0.0.0` 绑定所有网卡，请确保服务器无公网网卡、或防火墙已限制来源，避免暴露到公网。
- 不设置路由器端口转发。
- Windows 防火墙仅对 `PRTS` 所在专用网络放行：
  - TCP `8000`（网页）
  - UDP `5500`（节点遥测）
  - UDP `5501`（节点命令，本 Web MVP 可不开）

排查端口占用：

```powershell
Get-NetUDPEndpoint -LocalPort 5500 -ErrorAction SilentlyContinue
Get-NetTCPConnection -LocalPort 8000 -ErrorAction SilentlyContinue
```

不要同时运行旧的 `wificsi-server` 与新的 `wificsi-dashboard`，二者会争抢 UDP 5500。

## 7. 无硬件验证（模拟器）

未接入真板时，用模拟器做多节点与故障联调：

```powershell
# 每个模拟器使用不同 MAC
D:\Develop\uv\uv.exe run wificsi-simulator --host 10.204.75.168 --port 5500 --node-id 02:00:00:00:00:01 --rate 50 --duration 60
D:\Develop\uv\uv.exe run wificsi-simulator --host 10.204.75.168 --port 5500 --node-id 02:00:00:00:00:02 --rate 50 --duration 60
D:\Develop\uv\uv.exe run wificsi-simulator --host 10.204.75.168 --port 5500 --node-id 02:00:00:00:00:03 --rate 50 --duration 60
D:\Develop\uv\uv.exe run wificsi-simulator --host 10.204.75.168 --port 5500 --node-id 02:00:00:00:00:04 --rate 50 --duration 60
```

建议预留测试 MAC：`02:00:00:00:00:01` … `02:00:00:00:00:04`。

验证顺序：1 节点正常流 → 4 节点并发 → 单节点停机（观察该节点变离线）→ 单节点新 boot 重启 → 服务器重启（节点周期 HELLO 后自动重发现）→ 慢 WebSocket 客户端。

## 8. 多节点联调验收

1. 逐块烧录并记录 STA MAC。
2. 每块单独确认 HELLO / CSI / SENSING_STATE / HEARTBEAT 四类消息齐备。
3. 同时上电 2 块，确认节点 ID、CSI、状态不串。
4. 同时上电 4 块，运行至少 30 分钟，观察内存有界、无持续线性增长。
5. 检查 `queue_dropped`、`udp_send_errors`、`sequence_gaps`、`duplicates`、`out_of_order`，区分设备丢弃、UDP 链路问题与 UI 主动合并。

## 9. 常见问题排查

| 现象 | 排查顺序 |
| --- | --- |
| 页面有节点但图表不动 | 确认 CSI 计数增长 → observer 收到合法 CsiFrame → hub 派生 → publisher flush → WebSocket 订阅 → 前端 reducer 未丢事件 |
| 图表更新导致 UDP 丢包 | 确认 observer 无 JSON/await/重计算；确认未按源 CSI 帧广播；确认慢客户端邮箱有界 |
| 状态错显示为“无人” | 只检查 `lifecycle → presence` 映射；INITIALIZING/OFFLINE 必须分别显示 |
| 多节点串数据 | 全程使用规范化 `node_id`（小写冒号 MAC），勿用 IP/端口/数组下标做身份 |
| 页面越跑越慢 | 确认每节点趋势裁剪为 600 点；ECharts 未重复 init；断开 WS 的 sender task 已清理 |
| 启动报地址占用 | 用只读命令查明占用者，勿同时跑两个服务器 |
| WebSocket 无法建立 | 确认已安装 `websockets`（`uv sync --all-groups` 会安装）；查看服务器日志是否提示缺少 WebSocket 库 |

## 10. 安全边界

- 本阶段无认证、加密、授权，仅用于可信局域网。
- REST 与 WebSocket 均为只读，不暴露 UDP 命令通道。
- 不在 API、日志或错误信息中返回 Wi-Fi 密码、原始 CSI I/Q 或局域网凭据。
- 若未来需要远程访问、登录或网页控制节点，必须重新进行安全设计。
