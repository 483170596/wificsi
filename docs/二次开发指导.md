# WIFICSI 二次开发指导

本文面向需要在现有基础上扩展功能的开发者，说明代码架构、数据流、关键扩展点与约定。

## 1. 代码架构总览

```text
server/wificsi/
├── protocol.py       Stage 2：WCSI v1 二进制协议严格编解码（不改）
├── registry.py       Stage 2：节点生命周期与链路计数（事实来源）
├── ingest.py         Stage 2：UDP 接收 + accepted observer（已扩展）
├── commands.py       Stage 2：UDP 命令事务（本 Web MVP 不调用）
├── server.py         Stage 2：无头 CLI（保留）
├── simulator.py      Stage 2：确定性节点模拟器
└── web/              Stage 3：看板后端
    ├── settings.py   运行时配置
    ├── models.py     JSON v1 模型 + presence 映射 + MAC 助手
    ├── transform.py  I/Q → 幅值等纯函数
    ├── stream.py     NodeStreamHub 有界实时派生
    ├── connections.py WS 连接管理与合并邮箱
    ├── runtime.py    UDP + registry + hub + publisher 组合
    ├── api.py        REST 路由 + WebSocket 路由 + SPA 托管
    └── main.py       wificsi-dashboard CLI 入口

web/                  看板前端
├── src/api/          contracts.ts / http.ts / socket.ts
├── src/state/        dashboard.ts（reducer/store）
├── src/components/   PresenceBadge / NodeCard / NodeGrid / 图表
└── src/pages/        DashboardPage.tsx
```

关键原则：浏览器 API 不复制、不修改、不重新解释 WCSI 二进制协议；`NodeRegistry` 是节点生命周期的唯一事实来源；`NodeStreamHub` 只为实时展示服务，不把历史塞回 registry。

## 2. 后端数据流

```text
UDP datagram
  → decode_packet（严格解码，坏包计数并丢弃）
  → registry.accept（更新节点生命周期/计数，返回是否接受）
  → accepted observer → NodeStreamHub.offer（O(1) 覆盖最新 CSI 槽）
publisher（10 Hz asyncio task）
  → registry.expire()（5 秒离线判定）
  → hub.flush_latest()（I/Q 派生 + 追加有界环形缓冲）
  → connections.publish()（按订阅过滤，合并邮箱投递）
WebSocket sender task
  → mailbox.next_event() → websocket.send_json()
```

- observer 必须同步、零等待，禁止 JSON 编码/磁盘 I/O/await；异常被隔离并计入 `observer_errors`。
- 每节点派生环形缓冲最多 `max_history`（默认 100）点，节点数上限 `max_nodes`（默认 16）。
- `boot_id` 变化时清空该节点派生缓冲，避免把重启前后画成一条连续曲线。

## 3. 前端数据流

```text
DashboardPage
  ├─ 挂载时 fetchNodes() → SNAPSHOT（初始快照）
  └─ createSocket()（单连接 + 退避重连）
       ├─ hello     → HELLO（记录 server_instance_id，变化则清空 streams）
       ├─ nodes_snapshot → SNAPSHOT（替换 nodes，保留同 boot_id 曲线）
       ├─ node_status    → NODE_STATUS（更新单节点）
       └─ csi_batch      → CSI_BATCH（更新 latest + 追加 history，裁剪到 600 点）
```

- 所有键先把 MAC 规范化为小写冒号格式。
- 每个节点趋势历史独立，最多 600 点，不得用一个全局数组混放。
- 当前选中节点离线时保持选择，不自动跳转。
- WebSocket 断开时展示“连接中断”，节点卡保留最后已知状态并加“过期”遮罩，不把所有节点立即标成“无人”。

## 4. 常见扩展点

### 4.1 给节点增加展示字段

1. 后端：在 `web/models.py` 的 `NodeSummary` 加字段，并在 `build_node_summary()` 中从 `NodeSnapshot` 取值。
2. 前端：在 `web/src/api/contracts.ts` 的 `NodeSummary` 同步类型；在 `NodeCard.tsx` 或 `HealthPanel` 渲染。
3. 更新对应测试（`tests/server/web/test_models.py`、前端 reducer/组件测试）。

### 4.2 增加只读 REST 端点

在 `web/api.py` 的 `create_app()` 内新增路由，通过 `request.app.state.runtime` 访问运行时；复用 `models.py` 的 builder。遵循 `/api/v1/*` 前缀，返回 UTF-8 JSON。

### 4.3 增加 WebSocket 事件

1. 在 `runtime._publish_once()` 或新增 publisher 分支中构造事件并用 `connections.publish(event_type, node_id, envelope)` 推送。
2. 在 `connections._Connection.accepts()` 中决定该事件是否受订阅过滤（如全量事件直接返回 True）。
3. 前端在 `socket.onEvent` 的 switch 中处理新 `type`，并在 reducer 增加对应 action。

### 4.4 增加图表

在 `web/src/components/` 新增图表组件：用 `useRef` 创建一次 ECharts 实例，`setOption` 增量更新，卸载时 `dispose()`，`animation: false`，窗口 resize 时 `resize()`。在 `DashboardPage` 的详情区挂载并传入对应 `state.streams` 数据。

### 4.5 调整容量

`web/settings.py` 的 `max_nodes`（默认 16）、`max_history`（默认 100）与 `publish_hz`（默认 10）可改；前端 `state/dashboard.ts` 的 `HISTORY_LIMIT`（默认 600）需同步。所有内存容器必须有固定上限，慢消费时丢旧“显示帧”，绝不阻塞 UDP 接收。

### 4.6 增加节点控制（需另行设计）

当前 REST/WS 均为只读，Stage 2 的 UDP 命令通道未暴露为 HTTP。若要支持网页改灵敏度/重置基线，必须先补安全与权限边界，不要在节点详情组件中顺手加按钮。

## 6. 约定

1. `protocol.py` 与固件 WCSI v1 保持不变；Web JSON v1 独立。
2. 节点身份始终使用规范化小写冒号 MAC，不用 IP、UDP 源端口或数组下标。
3. 新增依赖只放受控版本范围；核心 Stage 2 测试保持快速。
4. 不新增历史数据库、录制、下载、模型推理、用户系统或远程访问——它们超出本阶段边界。
5. 错误信息不泄漏 traceback、凭据或原始 UDP/IQ 数据。

## 7. 环境提示

- 后端通过 `uv` 管理，`pyproject.toml` 依赖 `fastapi`、`uvicorn`、`websockets`、`pydantic`。
- 前端锁定 `web/package-lock.json`；`web/dist` 与 `web/node_modules` 不入库。
- 真板联调前先用模拟器跑通多节点与故障场景。
